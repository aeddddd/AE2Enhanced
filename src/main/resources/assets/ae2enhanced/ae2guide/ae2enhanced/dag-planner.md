# 合成计划引擎

AE2Enhanced 内置的合成计划引擎, 自 1.1.0 起默认接管所有下单的计划计算,
原生 AE2 的递归算法作为回退路径保留. 本页完整说明其能力、使用条件与工作原理.

## 能力

**大型订单的计划提速.** 原生 AE2 的计划算法是递归展开配方树: 同一中间材料出现在
多个分支中时会被重复计算, 且递归深度和迭代次数存在上限, 深层或数量大的订单会直接失败.
计划引擎改为先将配方关系编译为图、再单趟求解(见[工作原理](#工作原理)),
消除了重复计算与递归上限, 大型订单的计划耗时显著降低.

**支持原生无法计划的配方结构.** 以下结构在原生 AE2 中会被判定为递归而拒绝,
计划引擎可以正确生成计划:

* **自增殖配方**: 产物同时是自身原料且净产出为正, 如锻造模板复制
  (`1 模板 + 7 钻石 + 1 下界岩 → 2 模板`). 网络中持有至少 1 份产物作为种子即可下单,
  执行结束后种子保留在网络中;
* **跨样板循环链**: 多个样板的输入输出首尾相接且整体净增殖,
  如赛特斯石英循环(`水晶→粉`、`水晶→充能水晶`、`粉+充能水晶→水晶`).
  引擎对循环整体配平, 给出各样板调用次数与启动种子需求;
* **循环的环外副产物**: 循环每运转一轮额外产出环外物品时
  (如 `1A → 1X + 1B`、`1B → 1A` 中的 X), 可以直接下单该副产物.
  原生 AE2 按主产出索引样板, 无法识别经副产物闭合的循环, 此类订单在原生下报告缺料;
* **深层特殊结构**: 订单的中间材料涉及上述任一类结构时
  (例如某机器零件需要锻造模板), 引擎在编译期识别并接管对应子图, 其余部分正常展开.
  原生行为是整单失败.

**计划确认界面增强.** 每个处理样板条目追加显示 `调用 N 次·约 R 轮`
(轮次按当前选中 CPU 的协处理器数估算, 切换 CPU 时联动);
循环/自增殖条目显示 `循环·分 R 轮` 或 `自增殖·N 次`,
悬停可查看每轮消耗、每轮产出、总轮次与初始提取的完整明细.

**特殊任务的执行隔离.** 含循环内容的计划自动路由到本模组的虚拟合成单元
(测试合成 CPU / 超因果计算核心)执行, 按轮次配额调度各样板的推送节奏,
不会发生样板互相等待的死锁, 任务结束后 CPU 内无物品残留.
不含循环内容的计划在普通 CPU 上执行, 行为与原生完全一致.

## 使用条件

普通订单无任何条件. 涉及循环/自增殖的订单需要:

* **启动种子**: 每种循环物品需要网络中持有一定数量作为启动库存,
  通常等于该物品每轮的消耗量(例如赛特斯循环下单 1000 水晶, 需要 128 水晶 + 64 充能水晶).
  确认界面的"初始提取"一栏会列出确切数量;
* **虚拟合成单元**: 网络中须建有测试合成 CPU 或超因果计算核心.
  循环类任务只会派发给虚拟合成单元; 若网络中没有, 此类任务无法提交.

引擎遇到无法处理的情形时(见下文回落条件)自动退回原生算法,
该订单的行为与未安装引擎时一致, 不会因此失败.

## 配置

`config/ae2enhanced-common.toml`:

```toml
[craftingPlan]
# DEFAULT: 所有下单优先由引擎计算, 原生算法作回退(默认)
# FALLBACK: 先由原生算法计算, 无法得出完整计划时由引擎重算
# OFF: 停用引擎, 全部使用原生算法
dagPlannerMode = "DEFAULT"
```

## 工作原理

本节面向希望了解实现的读者, 非使用必需.

### 1. 编译: 配方关系 → 有向无环图

下单时引擎从网络的样板索引出发, 将配方关系编译为 DAG:

* **节点合并**: 节点 = (物品, 选定样板). 同一物品在不同分支重复出现时合并为唯一节点,
  重复子树只编译一次——这是相对递归树的主要提速来源;
* **两遍编译与环检测**: 第一遍深度优先遍历只做环检测, 发现回边时将其目标记录为
  循环边界; 第二遍正式建图, 边界物品收缩为叶子节点(类型 CYCLE),
  其输入不再展开. 其余节点按语义分类为: 普通(可合成的干净样板)、
  发射台(由 Level Emitter 提供)、终端(无样板, 记为缺料);
* **保守接管**: 含 tag/替代输入的样板不参与编译,
  遇到时整单回落原生算法, 以保证语义与原生逐字节一致.
  容器物返还(如蜂蜜瓶返还玻璃瓶)不是限制: 原生对此类样板逐次循环,
  引擎按"消耗 N 份、回记 N 份容器"批量一次算完, 结果与原生全等且更快.

### 2. 执行: 拓扑顺序单趟扫描

编译产物按逆后序(需求方先于原料方)扫描一趟: 每个节点的需求量由父节点沿边累加得到,
先以网络库存精确抵扣(含 NBT 变体的模糊匹配), 缺口换算为样板调用次数(向上取整),
次数再乘各输入倍率传播给子节点; 所有产出(含副产物)按次数回记库存.
最终由与原生相同的函数生成计划对象(调用次数、库存提取、缺料报告、发射物品).

引擎在交付前经过对齐测试矩阵验证: 同一批订单下引擎计划与原生计划逐项全等,
确认默认接管无行为漂移.

### 3. 循环子图: 闭式求解

类型为 CYCLE 的边界节点在执行扫描推进到它时, 其外部需求量已经确定,
引擎将对应循环子图交给循环求解器, 按结构分别处理:

* **自增殖**(单样板自环): 调用次数 = ⌈需求量 ÷ 每次净产⌉, 闭式直接得出;
* **跨样板循环**: 以"样板 × 物品"精确系数矩阵建立平衡方程组,
  求正整数零空间向量得到各样板的执行次数比与每轮净产出, 需求量除以每轮净产出即为轮数;
  多个循环共享中间样板时(θ 形结构)对候选环取并集联立求解;
* **催化环**: 循环守恒(中性)或增殖但每轮发射环外副产物时,
  轮数 = ⌈副产物需求 ÷ 每轮发射量⌉, 循环物品只需种子不消耗;
* **启动种子**: 对各循环物品做前缀分析, 得出"任意推送顺序下都不会断料"的最小启动库存;
  种子在计划中以"初始提取"记账, 执行结束由系统返还网络.

求解结果(各样板调用次数、种子、辅材消耗)并入总计划, 与 DAG 部分统一输出.

### 4. 执行期: 轮次配额调度

含循环内容的计划在虚拟合成单元上执行时, 引擎从计划的调用次数中恢复循环结构
(既消耗又产出的物品构成环键, 各样板调用次数的最大公约数即轮数),
并对环上样板的推送施加配额: 任一已完成的超轮数不超过最慢样板时,
才允许推送下一轮. 这防止了 CPU 的贪婪推送让某个样板一次性耗尽共享材料、
使其余样板永久等待的死锁. 配额机制只作用于含循环的任务, 普通任务的推送不受任何干预.

### 5. 回落条件

以下任一情况, 引擎整单退回原生算法(该订单行为与未安装引擎一致):

* 样板含 tag/替代输入;
* 循环边界无法求解(启动种子不足、欠定结构、耗散环等);
* 计算策略为 CRAFT_LESS 等非标准模式;
* 引擎内部发生任何异常.
